# Evaluation

All numbers below are regenerated by code in this repository (`python -m pramaan benchmark`, `pytest`). CI runs both on every push.

## 1. Hyderabad-scale benchmark

`pramaan/benchmark.py` generates a synthetic outdoor homicide scene with 200 free-text exhibits from a fixed seed (2019): near-duplicate litter concentrated 15–220 m from the body (lorry parking, dhaba, bus shelter), a few traces and weapons near the body, impressions still at the scene, perishable toxicology, CCTV that overwrites. Five **needles** are inserted at random list positions.

### Needles

| Needle | Exhibit | Listed at | Ranked | Tier | Type |
|---|---|---|---|---|---|
| NEEDLE-1 — half-burnt cigarette butt 3 m from the body | Ex-B8 | #8 | **#5** | P1 | cigarette_butt |
| NEEDLE-2 — viscera kept at ambient temperature | Ex-B13 | #13 | **#18** | P1 | viscera |
| NEEDLE-3 — toll-plaza CCTV not yet seized | Ex-B83 | #83 | **#29** | P1 | cctv_dvr |
| NEEDLE-4 — fingernail scrapings | Ex-B182 | #182 | **#16** | P1 | fingernail_scrapings |
| NEEDLE-5 — reference blood (FTA) | Ex-B186 | #186 | **#36** | P1 | reference_blood |

### Scheduling policies (stage-1 metrics)

| Policy | Value retained | Perishable value | Late | P1 mean (working days) | Makespan (working days) |
|---|---|---|---|---|---|
| **Pramaan** `atc(k=4)` | 93.2% | 90.9% | 0 | 6.6 | 35.1 |
| Status quo (all, listing order) | 85.5% | 80.5% | 13 | 29.29 | 125.4 |
| FIFO (stage-1 set) | 93.1% | 90.7% | 0 | 10.63 | 33.9 |
| Static EPI sort (stage-1 set) | 92.8% | 90.3% | 0 | 6.05 | 33.8 |

*Value retained* = EPI-weighted evidential quality at the start of each exhibit's first destructive examination. *Status quo* = every exhibit (including the 124 held duplicates) examined in listing order. FIFO and static sort use Pramaan's stage-1 set, which separates the effect of **staging** (status quo → FIFO) from the effect of **ordering** (FIFO → Pramaan: mostly faster P1 results). Throughput: 200 exhibits triaged in 0.42 s (474 exhibits/s) on a laptop-class CPU.

**Lesson recorded honestly:** a *static* "sort by score" is not automatically better than FIFO — on large queues it can retain *less* value because it ignores due dates. That is why the recommended plan comes from a due-date-aware portfolio and is always shown next to its baselines.

## 4. Scale test

`python -m pramaan scale --cases 10 --items 200`: 2000 exhibits triaged in 4.51 s; network plan P1 38.39 vs 84.85 days (HQ-only), makespan 312.0 vs 492.0 days, late 407 vs 613, planned in 10 ms. See [fsl-scalability.md](fsl-scalability.md).

## 5. Limitations and threats to validity

* **Synthetic data.** Scenarios are modelled on published patterns, not real case files. Field validation with an FSL is the next step.
* **Heuristic constants.** Half-lives, examiner counts, exam hours and weights are illustrative planning values, versioned in YAML so experts can calibrate them; every result records the KB hash it used.
* **Keyword classification.** Unusual phrasing may fall back to *Other object* (flagged for manual review) unless the optional watsonx.ai layer is enabled.
* **Photos.** Coverage is checked via captions only; no computer vision yet.
* **Scheduler.** Dispatch heuristics, not an exact optimiser; examiners are assumed interchangeable within a division.
